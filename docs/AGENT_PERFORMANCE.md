# Agent 场景性能专项 / Agent performance suite

适用于 1.10.3。Agent 默认关闭，使用独立输出配额。

## 1. 产品边界

评估当前模型服务在长上下文、多会话并发、多轮工具 Loop、思考模式和可选图片/音频输入下的性能。报告章节固定为“Agent 能力评估”，其中包含实测数据与确定性规则结论；不评价业务任务正确率、工具选择水平或通用智能，不给能力总分。Thinking 不是启用专项的前提，沿用本次配置选择的 off/on 模式。

集成现有脚本，默认关闭。运行顺序为常规测试 → Agent 专项 → 已启用的模型自评 → 最终报告。关闭或删除配置块时不增加请求、证据文件或报告章节，不改变常规计划和统计。暂不提供仅运行专项的入口。

## 2. 配置与请求计划

在现有 JSONC 顶层添加以下配置；最简可只填写 `{"enabled": true}`，其他字段采用下面的默认值：

```jsonc
"agent_performance": {
  "enabled": true,
  "output_tokens": {"off": 4096, "on": 16384},
  "scenarios": ["long_context", "loop"],
  "concurrency": [1, 5, 10],
  "repetitions": 3,
  "long_context": {
    "input_characters": [8192, 32768, 65536, 131072]
  },
  "loop": {
    "tool_choice": "named", // named 指定工具；auto 自动选择，不自动回退
    "initial_input_characters": 8192,
    "model_calls_per_session": 10,
    "tool_result_characters": 2048,
    "tool_delay_ms": 0
    // "session_timeout_seconds": 1200
  }
}
```

会话总超时默认等于模型调用次数 × 单请求总超时 + 工具调用次数 × 工具延迟；可指定正数，最多 86400 秒。示例添加该字段时需补上前一行的逗号。专项并发支持 1～10，重复次数 1～1000，初始/单轮输入 128～1048576 字符，Loop 2～100 次模型调用，工具结果 128～65536 字符、等待 0～60000 ms。每次序列化请求不超过 16 MiB。

模型连接、思考模式、请求超时、种子和预热策略继承本次运行。1.10.2 起，`agent_performance.output_tokens` 独立设置每次模型调用的输出上限，默认 off=4096 / on=16384 Token，两个字段均须为 1～65536 的整数。配额包含服务计入输出用量的思考 Token，适用于长上下文、工具 Loop 每轮及最终回答、图片/音频的预检、预热和正式请求；它不是整条会话共享的配额。顶层 `output_tokens` 继续只控制常规测试，模型自评配额不变。更高上限不保证没有截断，也不会强制模型输出到上限；服务上下文窗口和超时仍然有效，不自动重试或隐藏截断。字符数不是 Token；Token 只采用服务 usage。数组可逐行注释，但启用场景及所需数组不得为空。

`--dry-run` 在不发起 HTTP 请求的情况下展示展开后的计划、独立输出配额、引用关系、新增请求上限、Loop 会话/工具次数上限和预检/预热数。使用默认模板的双模式与独立配额时，不复用输出预算不同的常规请求；新增性能请求最多 1344 次，其中长上下文 384 次、Loop 96 条会话最多 960 次模型请求、864 次工具执行。另有专项预检 12 次、默认预热 28 次，总计最多新增 1384 次模型请求。关闭预热则最多 1356 次。若把专项配额设为与常规一致，可恢复符合全部条件的引用。失败/取消会减少实际执行量；改配置后以 dry-run 为准。

## 3. 常规数据复用与独立测试

长上下文场景仅引用同次运行中字符档位、并发、重复次数及该模式输出配额完全一致的常规组合。专项独立配额不同时单独测量，不能用较低输出预算的常规数据代替。其余影响可比性的模型/协议参数、输出要求、超时、生成器、种子策略和预热策略均继承同一个冻结配置。计划展开时固定引用关系，保留原请求 ID 和统计；不跨历史运行缓存数据。

缺少或不匹配的长上下文组合单独补测。已经引用的基线若失败、缺 usage 或未完成，保留该状态，不静默补跑。Loop、图片和音频全部单独测量，不能由普通文本请求推导。报告标明“常规基线引用”或“专项实测”，引用不增加请求、Token 或样本计数，也不合并不同调度窗口计算总吞吐。

Loop 每批启动指定数量的会话，各会话独立串行推进，整批结束后进入下一批，不补充新会话。默认一条会话含 9 次工具调用请求和 1 次最终回答请求。工具为固定本地 `benchmark_step({"operation":"measure"})`，返回受控文本，不执行模型给出的代码、路径或 URL。最终回答轮通过 `tool_choice: none` 关闭工具。`loop.tool_choice` 从 1.10.1 起可显式选择 `named`（默认，指定函数）或 `auto`；同次运行固定，不在失败后切换。服务需要接受 `tools`、所选 `tool_choice`、`parallel_tool_calls: false` 及流式工具参数；本次预检失败只表示该配置没有完成流程，不能直接断言模型不支持工具。

1.10.1 使用 `agent-loop/v2` 负载：初始上下文和工具结果为精确字符长度的纯数据，每轮单独追加一次工具调用指令，最后追加明确收尾指令；额外指令与历史均计入真实请求长度和 Token。常规文本负载生成器不变。工具选择与负载版本随计划及请求保存，报告展示所选方式；旧 1.10.0 证据仍可离线重建。

工具要求严格 Schema，唯一必填参数为 `operation="measure"`，拒绝额外参数。工具片段必须完整组装并通过参数校验才可回传：auto 要求 `finish_reason=tool_calls`；named 接受 `tool_calls` 或 vLLM 指定工具路径的正常 `stop`。任何模式均拒绝 `length`；服务 usage 显示输出 Token 达到预算时，即使结束标记被服务覆盖，也按 `output_budget_exhausted` 终止会话，不执行工具。`output_budget_reached` 为客户端根据服务 usage 得到的保守判定，保留原始 finish_reason，不冒充服务明确报告截断。提前结束、错误工具/参数、截断、超时或取消会终止该会话；不重试、不降级为文本。继续会话所需的 assistant content、reasoning_content 和工具调用仅保存在内存。模型 API 的其他私有推理状态格式不在当前适配范围。

每种模式和每个新增负载有独立预检，Loop 预检是一次工具调用加一次最终回答。预热继承现有开关，使用完整独立会话；两者不进入性能样本。专项预检失败隔离相应负载，模式出现矛盾证据则停止该模式后续专项组合。

## 4. 图片与音频输入

本地当前测试选择图片输入，未启用音频或视频。仓库提供固定的非敏感 PNG 样本与标准库生成器，见 [图片样本说明](../samples/README.md)。在 `scenarios` 中加入 `image_input`，将下方图片路径换成 `samples/agent-image-grid.png`，分别设置 `count: 1` 和 `count: 4`，即可比较单张与同图四份的负载。四份重复图片不是四张不同图片的理解测验，服务可能复用媒体缓存。测试验证接口完成情况和性能，不评分图片描述的正确性。

在 `scenarios` 中加入 `image_input` / `audio_input`，并填写：

```jsonc
"media_samples": [
  {"kind": "image", "path": "samples/page.png", "count": 1},
  {"kind": "image", "path": "samples/page.png", "count": 4},
  {"kind": "audio", "path": "samples/voice.wav", "count": 1}
]
```

路径相对配置文件目录，也可为绝对路径。仅加载启用场景的样本；在任何网络请求前检查文件。图片支持 PNG，单边最多 8192 px，每组重复同一图片 1～8 份；音频支持 16-bit PCM WAV，单/双声道、8～48 kHz、最多 120 秒，每组一份。单文件最多 4 MiB，图片组原始大小最多 8 MiB。PNG 检查签名和 IHDR，不进行完整图像解码；服务端解码失败保留为预检失败。

图片通过 Chat Completions `image_url` 的内联 data URI 发送，音频通过 `input_audio` 发送，附固定文本负载，按并发矩阵测单轮性能。无远程下载、云端 OCR/ASR、视频或实时语音流程。是否支持必须由实际服务预检确认。

证据只存序号、种类、份数、格式、字节数、尺寸/时长和 SHA-256，不存文件路径、媒体正文或 base64。离线重建不需要原文件。样本对应的请求、用量与时序仍可审计，但哈希不能恢复样本内容。

## 5. 指标与结论

| 指标 | 定义及边界 |
| --- | --- |
| TTFT / TTFO、请求 E2E | 沿用常规文本语义定义；纯工具参数不冒充最终回答，失败耗时保留在证据及汇总 |
| 工具调用就绪时间 | 请求发起至工具调用按协议完整结束并通过校验；首片段时间另存 |
| 单请求 tok/s | 服务 Token 与首末生成区间可匹配才计算；纯工具参数或不可观测思考区间为 N/A |
| 聚合 tok/s | 成功协议请求的输出 Token / 各批观测窗口之和；单轮按最早请求开始至最后结束，Loop 按首会话开始至最后会话终止，包含工具和轮间等待、失败耗时 |
| 完整流程耗时/完成率/吞吐 | 完整会话的 P50/P95、完整会话/已启动会话、完整会话/观测窗口；不是业务任务正确率 |
| 逐轮结果 | 工具轮和最终回答轮分列，含成功/到达、输入字符/Token、工具就绪 P95、E2E P95；不同轮次窗口重叠，不计算逐轮聚合吞吐 |
| Token | 请求级 input/output/reasoning/cache；完整会话累计用量的分布，缺项不当零，累计输入包含反复发送的历史 |
| 稳定性与覆盖 | 失败、超时、截断、未决请求/会话、各轮到达数、usage 覆盖率、实际在途峰值；原始时序支持复算 |

分位数采用 nearest-rank。任何未决窗口或成功请求缺少输出 usage，完整聚合 tok/s 都为 N/A；保留已知用量及覆盖率。不能将单请求速率相加作为总吞吐，也不能称为 GPU 纯解码速度。

规则版本 `agent-rules/v1`：同条件相邻输入/并发档延迟上升或吞吐下降至少 20% 时指出位置、前后值、比例、样本与输出量；延迟指标至少有 3 个有效样本，组合必须完整、无失败和截断。后续档恢复则提示局部波动，否则描述后续观测仍较差；没有后续数据时不声称持续转折。分别给出并发吞吐收益和延迟代价、同类工具轮首末变化、思考配置差异及失败/覆盖结论。Loop 首末比较同时列有效样本数，存在提前退出时需结合逐轮到达数解释。20% 不是行业 SLA 或统计显著性阈值，少于 20 个样本的 P95 不代表稳定尾延迟。

可选 `targets` 按场景指定目标：

```jsonc
"targets": {
  "long_context": {"ttft_p95_ms": 2000, "min_output_tps_p50": 20},
  "loop": {"tool_ready_p95_ms": 3000, "session_p95_ms": 60000,
           "min_success_rate": 0.99, "min_session_completion_rate": 0.99}
}
```

这些数值仅为写法示例，不是推荐 SLA。支持 `ttft_p95_ms`、`ttfo_p95_ms`、`e2e_p95_ms`、`min_output_tps_p50`、`min_success_rate`；Loop 还支持 `tool_ready_p95_ms`、`session_p95_ms`、`min_session_completion_rate`。比例为 0～1 之间的正数，其余为正数。逐档显示实测值、目标和“本次观测达标 / 未达标 / 无法评估”；缺值或档位未完成不判断通过。当前不自动推荐最高容量或适用等级，Goodput、持续到达率负载和容量极限搜索不在范围内。

## 6. 报告与证据

顺序：基础结果与分析 → **Agent 能力评估** → 模型自评（若启用）→ 测量口径与附录。专项包括重点结论、场景数据表、Loop 逐轮表、思考对照表、补充分析及预检失败。MD/HTML 从同一个结构化数据源生成数值和结论；HTML 内联 SVG 展示 Loop 工具就绪和最高已测输入档的并发吞吐趋势，全部档位仍保留数据表。浅色、内容平铺、A4 纵向打印，无远程资源和切换操作。

新增 `agent_requests.jsonl`，版本 `inferpulse.standalone.agent/v1`；公式版本 `agent-client/v1`。原常规证据不改写。运行快照冻结专项配置、样本元数据、展开计划、引用关系、规则及公式版本；汇总增加可选 `agent_performance`。会话/请求身份、批次、轮次、父请求、工具时序、长度、哈希及结果状态保留，不存提示词、回答、思考、工具参数/结果正文和媒体正文。模型自评维持原有输入白名单，本轮不把专项汇总发送给模型，也不新增自评请求。

增量落盘与离线重建沿用现有入口。Ctrl+C 停止新调度、关闭连接；截断日志保留已写记录和未决状态。离线重建不访问当前 JSONC、媒体、工具或模型。旧快照没有专项字段时不产生专项章节，老指标与版本含义不变；1.9.0 读取器不支持新专项配置，读取 1.10.1 生成的新证据请使用 1.10.1 或后续兼容版本。


## 验证与报告

Python 3.9/3.13 各 132 项回归通过，含工具协议、图片输入、独立配额、截断、离线重建及样式基线。图片性能不等于识别准确率；音频是否支持取决于具体模型和服务。报告按结论、图表、明细展示，点击图形定位对应数据行。测量与发布边界见 [更新记录](../CHANGELOG.md)，视觉约束见 [样式规范](design/bench-report-style/README.md)。
