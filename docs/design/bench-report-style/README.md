# InferPulse Bench 报告样式规范

- 样式基线：**1.1**，2026-09-21 发布验收及用户追加调整。
- 适用范围：`llm_benchmark.py` 生成的动态 HTML 报告；Markdown 共用数据与结论，但不要求复制视觉组件。
- 当前状态：CSS/SVG 基线固化；Chrome A4 模拟样本覆盖双模式与 Agent、单模式、中断、无数据及跨页长自评。不同字体、浏览器与任意数据规模仍需按实际报告检查。
- 本文是后续报告改动的样式依据。早期 [A4 原型](../../../report.example.html) 仅提供历史参考，其固定 12 页布局不得覆盖本规范。

## 1. 保持的设计方向

浅蓝、白底、细分隔线，内容平铺。先结论，再图表，再明细；突出关键变化，减少阅读成本。不要加入下拉框、模式切换、Tab、折叠区或必须悬停才能读到的结论。

HTML 必须可以离线独立打开和打印；样式与 SVG 内嵌，不引入网络字体、图表 CDN、JavaScript 或外部 CSS 运行依赖。扩展内容使用现有视觉体系，不随功能迭代重新设计配色、卡片、标题和留白。

## 2. 信息顺序

| 顺序 | 内容 | 约束 |
| --- | --- | --- |
| 1 | 品牌、标题、模型/时间、执行计数 | 计数不等同于答案完整，不添加“测试完成”等装饰状态徽章 |
| 2 | 关键结论 | 协议结果、截断、缺失回答、Agent 闭环和未达标项优先，短句直述 |
| 3 | 关键场景双模式卡 | 放在报告开头；先选共有的最低输入，再最低并发；单模式或无共同场景不虚构另一侧 |
| 4 | 性能变化分析 | 最多 3 张 A/B/C 异常卡；无异常时短句说明，不制造异常 |
| 5 | 测试条件、模式验证、预热 | 保留有效性与执行边界，避免将 HTTP 接受等同于模式生效 |
| 6 | 双模式对照、各模式性能明细 | 对应图表在表格之前，保留完整数据与证据完整性 |
| 7 | Agent 能力评估（启用时） | 专项结论、场景图表及明细、Loop 逐轮和模式对照；图先表后 |
| 8 | 模型自评（启用时） | 保留原文与来源说明，不用模型自评代替实测结论 |
| 9 | 测量口径与附录、支持页脚 | 定义、限制及图形符号说明集中于末尾 |

图表已显示单位和数值时，不重复添加“浅 → 深”“共用色阶”等设计说明。必要的失败、截断、样本与测量边界必须保留；不得以精简文字为由隐藏失败。

## 4. 组件与数据语义

### 双模式卡

关闭 / 开启思考并排，顺序固定。四项核心指标为 TTFO P50、E2E P95、单请求输出速率 P50、实际输出 Token P50。同步展示输出预算、协议完成、截断、最终回答计数与非完整状态。

场景选择不按结果好坏排序、不跳过失败档。不同预算和实际长度下，不自动标记某一模式“胜出”。缺失值保留 N/A，不变成零。

### 异常卡与联动

A/B/C 编号贯穿卡片、图表节点、延迟/输出/证据明细重点行。卡片突出模式、固定条件、相邻变化区间、指标、变化百分比以及前一档/异常档/下一档绝对值；短句说明后续恢复或证据不足。样本、截断与实际输出不省略。

沿用性能检测规则，不为视觉效果更改阈值或筛选样本。当前常规规则为相邻完整且全部协议成功、各至少 3 样本，TTFT/E2E P95 上升或聚合吞吐下降至少 20%；按相对变化排序，同模式同变化轴不重复，最多 3 项。仅说明观测变化，不确认原因或容量上限。

卡片数值及 SVG 节点以原生锚点定位到相应指标行，目标行加深；重点行编号可返回异常卡。延迟、输出、Loop 逐轮使用各自目标，不能只跳到章节标题。打印时编号与重点标记仍可辨认，无需点击。

### 图表与表格

- 常规双模式对照：TTFO P50（秒）、单请求输出速率 P50（tok/s）并排色阶图，使用共同零点和最大值。
- 各模式明细：TTFO P95（秒）、聚合输出吞吐（tok/s）曲线；异常涉及 TTFT/E2E 时补充同名曲线，不混用指标。
- Agent：场景吞吐、Loop 工具就绪逐轮曲线及 E2E P95 / 聚合吞吐模式对照。
- SVG 宽度坐标统一为 680；折线图 viewBox 高度 260；色阶图每张最多 12 行，折线每张最多 4 条系列。更多组合分图，全量展示。
- 折线横轴使用真实数值位置，输入字符使用 log₂ 刻度；纵轴保留零基线。不得连接跨越缺失值的线段，不将缺失当零。
- 截断、未完成或有效样本少于 3 保留星号/空心点；必要说明仅在附录出现一次。表格保留精确值、单位和证据。
- 图形数值来自对应汇总指标；图中秒与表格毫秒必须正确换算。所有目标 ID 唯一、链接有效、内容转义。

### 模型自评

浅蓝大档位卡，档位只显示一次；来源/未经事实核验说明置于正文前，蓝色连续编号段落，请求信息置底。只在原文连续编号可识别时分段，以模型自身首句或引导句形成标题；不润色、删减或重新编写评语。

无有效档位不伪造档位；失败、截断、损坏及来源不一致明确呈现。自评始终在附录之前，与性能事实区分。

## 5. A4 与响应式约束

打印去除屏幕外背景及页面外边距，避免页边距重复。标题尽量与后文同页，表头跨页重复，表格行、单图和紧凑卡片避免拆开；长正文与自评自然分页，不使用固定高度截断内容。有正文的自评独立起页；未生成或失败状态随正文自然排版。Agent 专项独立起页，其他二级标题自然排版。附录仅保留必要口径，9 pt / 1.6；支持栏 10.5 pt、600 字重、浅蓝底色和边框。

双模式卡优先出现在首屏/首页关键结论之后；异常卡和后续章节不强塞首页。数据量或异常信息增加时允许自然分页，不能删内容换取固定页数。打印 A4、纵向、100% 比例，关闭浏览器额外页眉页脚；不同字体与浏览器仍需要实际验收。

## 6. 修改与验证

1. **只改内容或新增指标**：沿用本规范及现有组件，保持其他样式不变。运行相关报告回归；不更新样式快照来掩盖意外变化。
2. **有意改变布局或视觉规则**：说明具体差异与原因，在本文件递增样式版本、更新变更记录，并将相应 CSS/SVG 快照与代码一同审查。该流程用于记录已授权调整，不额外引入每次修改的审批。
3. **不要仅更新快照让测试通过**：先核对变更影响，再同步快照。禁止把真实模型配置、请求正文、自评或运行结果复制成公开测试样本；本目录关联快照仅含人工构造的布局测试值。
4. 运行已有检查：

   ```sh
   python3 -m unittest discover -s tests -p 'test_standalone_llm_benchmark.py' -k accepted_style_baseline
   python3 -m unittest discover -s tests -p 'test_standalone*benchmark.py'
   .venv/bin/ruff check --target-version py39 llm_benchmark.py tests/test_standalone_llm_benchmark.py
   ```

   完整测试使用本机 mock HTTP 服务，不请求真实模型。上述测试文件已被当前 CI 的 standalone-benchmark 作业收集，不需要新增工作流。
5. CSS 基线检查覆盖普通/Agent 打印分支；SVG 快照覆盖色阶、曲线、零值、缺失断线、空心点、重点编号和链接。现有报告测试另行覆盖章节顺序、双模式选择、异常关联、转义、自评原文及数据不变。
6. 样式变更后，还应查看桌面/窄屏及 A4 打印：长表、长模型名/错误、自评长段、单模式、无数据与中断。快照测试不能代替实际浏览器视觉检查；受环境限制未完成的验收必须明确记录。
